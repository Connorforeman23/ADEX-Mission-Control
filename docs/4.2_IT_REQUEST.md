# Request to IT — Microsoft 365 app registration for ADEX Mission Control

Hi,

We're connecting our in-house CRM (ADEX Mission Control) to Microsoft 365 so that
staff can, individually and by their own choice, link their own mailbox to it.
The CRM will read a person's own mail to attach messages to the client or
supplier they relate to. **It does not send mail, and it cannot read anyone
else's mailbox** — each person signs in themselves and grants access to their
own mailbox only.

Nothing needs installing. It is one app registration in Entra ID (Azure AD).

## Please create

**Entra admin centre → Applications → App registrations → New registration**

| Setting | Value |
|---|---|
| Name | `ADEX Mission Control` |
| Supported account types | **Accounts in this organizational directory only** (single tenant) |
| Redirect URI — platform | **Web** |
| Redirect URI 1 | `https://adex-mission-control.vercel.app/api/microsoft/callback` |
| Redirect URI 2 | `https://adex-mission-control-git-dev-adex3.vercel.app/api/microsoft/callback` |

(Both URIs on the same registration — the second is our test environment.)

**Authentication** → leave "Implicit grant" unticked. Allow public client flows: No.

**API permissions** → Add a permission → Microsoft Graph → **Delegated** (not
Application):

- `User.Read`
- `Mail.Read`
- `offline_access`

Then **Grant admin consent for Advertising Excellence Ltd**, so individual staff
aren't each prompted for consent (or blocked by policy) when they sign in.

Please do **not** add any *Application* permissions — the CRM must not be able
to read mail without a signed-in user.

**Certificates & secrets** → New client secret → description `Vercel`, expiry
**24 months**. Please note the expiry date somewhere; we'll need a new one
before it lapses.

## Please send back (securely — not in plain email)

1. **Application (client) ID**
2. **Directory (tenant) ID**
3. The **client secret value** (shown once, on creation — copy it then)
4. The secret's expiry date

A password manager share or a Teams message that you delete afterwards is fine.

## One check

If the tenant has a policy that blocks users from consenting to apps, the admin
consent step above covers it. If there's anything else in place that would stop
a user signing in to a single-tenant app with delegated permissions (Conditional
Access on OAuth apps, for example), please let us know.
