# Package 1.5 — Auditability and offboarding

Read-only assessment 11 Aug 2026 and the agreed build.

## Gaps found
- **No audit trail.** Nothing recorded who changed or deleted any record. No
  accountability for financial or client-data changes.
- **Offboarding broken.** Removing someone from the staff list only blocked future
  sign-ups; an existing login kept working. No "disable now" control, and the app
  layout would even let a profile-less but authenticated user in as "standard".

## Decisions (11 Aug 2026)
- **Audit scope:** core financial/client/security tables — campaigns, campaign_lines,
  clients, leads, client_invoices, supplier_invoices, profiles. (Contacts/creative/
  tasks left out to keep the log signal-rich.)
- **Audit visibility:** admins only.
- **Offboarding:** in-app Disable (immediate lockout) + Supabase login delete for
  permanent removal.

## Build
**Database (`0005_audit_offboarding.sql`):**
- `audit_log` table, append-only, RLS = admins read only, written solely by a
  security-definer trigger (`audit_row`) attached to the seven core tables.
  Records actor, time, action, table, row id, changed fields, and a label.
- `profiles.active` flag; `admin_set_active(email, active)` (admin-only, can't
  disable the last active admin); `admin_list_staff()` rebuilt to include `active`.

**App:**
- `src/proxy.ts` — every request checks the signed-in user's `active`; a disabled
  user is bounced to /login with a message. Lockout takes effect on the next click.
- `src/components/TeamAdmin.tsx` — Disable/Enable button and a "Disabled" badge.
- `src/components/ActivityLog.tsx` + Settings — admin-only "Activity log" card.

## Offboarding — the two steps
1. **Disable** (in-app) → immediate lockout, record + history retained.
2. **Delete the login** in Supabase (Authentication → Users) → permanent removal;
   this also invalidates their session and cascades their profile away.

Disable is the fast, reversible switch; the Supabase delete is the permanent one.
Note: the middleware lockout is the immediate control for an active session; full
revocation of all access is the Supabase user deletion.
