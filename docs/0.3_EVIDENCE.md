## A real bug caught on preview, not production

The first preview failed to load. Cause: the guard read `NEXT_PUBLIC_*`
variables through a dynamic helper, which Next.js cannot inline, so the edge
runtime (middleware) saw them as empty and refused every request. Fixed by
reading them by their literal names. **This would have taken the live app
down for the whole team had it been pushed straight to production** — instead
it surfaced on a preview against the dev database, which is exactly what the
dev/preview split exists for.
