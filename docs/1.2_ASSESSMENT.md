# Package 1.2 — Harden authentication and administration

Read-only assessment (11 Aug 2026) and the agreed scope. No production change
was made during assessment.

## Current state

- **Login:** email + password via Supabase. Sound.
- **Sign-up:** self-service at `/signup`, gated to a `staff_roles` allow-list in
  the page AND by the `handle_new_user` DB trigger. Good.
- **Roles:** admin / standard / restricted. `guard_profile_fields` trigger (1.1)
  stops non-admins changing role/email/sales/id.
- **Team management:** no UI — done by hand-editing `staff_roles` in SQL.
- **Password reset / invites:** rely on Supabase's built-in email; no SMTP.

## Findings (ranked)

| # | Finding | Severity | Disposition |
|---|---|---|---|
| 1 | No SMTP → password reset unreliable in production | High | **Deferred** to the Office 365 migration (~end Aug). Interim: admin resets via dashboard. |
| 2 | Removing from `staff_roles` does not revoke an existing login | High | **1.5 (offboarding)** — flagged, not fixed here. |
| 3 | Supabase password policy weak (min 6, breached-password check off) | Medium | **Done** — Connor set min 8, breached-password ON, OTP expiry 15 min (11 Aug). |
| 4 | All team management is raw SQL | Medium | **Fixed here** — admin panel + `admin_*` functions. |
| 5 | `is_staff_email` callable by anon (email enumeration); 1-hour OTP | Low | Accepted for now (sign-up needs the pre-auth check; OTP shortened). |
| 6 | No 2FA | Medium | **Deferred** — own piece later. |

## Agreed scope for 1.2

**In:** password-policy hardening (done via dashboard); minimal admin panel to
add/remove staff-list entries and set roles, backed by security-definer
functions that verify the caller is an admin.

**Deferred:** SMTP (to M365 migration); 2FA.

**Out (later packages):** revoking/disabling existing accounts → 1.5.

## What was built

- `supabase/migrations/0003_admin.sql` — `is_admin()`, `admin_list_staff()`,
  `admin_add_staff()`, `admin_set_role()`, `admin_remove_staff()`. Each checks
  `is_admin()` and fails closed. `staff_roles` stays RLS-locked; the browser
  only reaches it through these functions. Includes a "cannot remove the last
  administrator" safeguard.
- `src/components/TeamAdmin.tsx` — admin-only UI on Settings.
- `src/app/(app)/settings/page.tsx` — renders the panel only when the signed-in
  user is an admin.

Remove-from-list is deliberately labelled in the UI as *not* logging an existing
user out — that honesty matters, and the real revocation is 1.5.
