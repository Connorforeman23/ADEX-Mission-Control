# Package 4.1 — Xero connection (proof of connection)

**Status: PROPOSAL for Connor's approval. Nothing built yet.**
Dev only. No production change in this package.

## Why now, and what changed

Connor is on a **Xero trial**, so Xero does **not** hold the historic 750–1000 POs.
That corrects an earlier assumption: **Xero is not the source for the historic
import** — that data still has to be collated and bulk-imported separately.

Xero's value here is **forward-looking**: once connected, client invoices and
supplier POs stop being double-entered. Wiring it up during the trial also makes
the trial a real evaluation — judging Xero as ADEX would actually use it.

## Scope of this package — deliberately thin

A **proof of connection**, not the full sync. Three things:

1. **Connect** — an admin-only "Connect Xero" flow on Settings (OAuth 2.0).
   Hardest part technically, so it is proven first.
2. **Read** — pull the Xero contact list and show how it would map to
   organisations. Proves the read path and the mapping question.
3. **Write one thing** — push a single client invoice into Xero **as a draft**.
   Draft means a human still approves it inside Xero; nothing is sent to a client
   by the CRM.

Then stop and review before building the full sync.

### Explicitly out of scope for 4.1
- Supplier bills / PO push (next slice)
- Automatic invoice matching against POs
- Background or scheduled sync (deliberate — see "no service key" below)
- Anything touching production or a real Xero organisation

## Safety design

**Test data only.** Dev CRM ↔ Xero's built-in **Demo Company** (fake, resettable,
and it outlives the 30-day trial). No real accounts touched.

**Two Xero apps, not one** — separate credentials for dev and production, mirroring
the environment separation from 0.3. Each app has its own fixed redirect URI, and
the stable `dev` branch URL makes that possible.

**Secrets stay server-side.** `XERO_CLIENT_ID` / `XERO_CLIENT_SECRET` are set
**without** the `NEXT_PUBLIC_` prefix, so they are never inlined into browser
JavaScript. (This is the same trap that broke the 0.3 preview — worth stating
explicitly.) They are optional: the app must start and run normally when Xero is
not configured.

**Tokens are unreachable from the browser.** A `xero_connection` table with RLS on
and **no policies** — the same pattern as `staff_roles` — readable only through
security-definer functions that check `is_admin()`.

**No service-role key is introduced.** Sync is user-triggered by an admin, so it
runs under that admin's session. This keeps the app's "no god-mode key" property
from the security programme. Background sync would need one, which is precisely
why it is out of scope here.

**Audited.** Connecting, disconnecting and any push are recorded, so there is a
trail of what left the CRM.

## Scopes requested from Xero
`openid profile email offline_access accounting.contacts.read accounting.transactions`

Read contacts; create draft invoices; refresh token. Nothing broader.

## Acceptance criteria
| Criterion | How it's proven |
|---|---|
| Admin can connect the dev CRM to the Xero Demo Company | Settings shows "Connected", with the Xero org name |
| Non-admins cannot see or use the connection | Standard user sees no Xero panel |
| Tokens are not reachable from the browser | Direct query as a signed-in user returns nothing |
| Secret is not in the browser bundle | Search built JS for the secret → 0 hits |
| Xero contacts can be read | Contact list renders in the CRM |
| One invoice pushes as a **draft** | Appears in Xero Demo Company as Draft |
| App still works with Xero unconfigured | Dev preview without the env vars runs normally |
| Disconnect works | Tokens removed; status returns to "Not connected" |

## Risks
- **Redirect URI mismatch** is the classic first-time failure. Mitigated by the
  stable `dev` branch URL and registering it exactly.
- **Token refresh** — Xero refresh tokens rotate on use; storing the new one every
  refresh is essential or the connection silently dies. Called out so it is built
  in, not discovered later.
- **Trial expiry** — the Demo Company survives it, so testing can continue.
