### Process note
The 1.5 PR (frontend) was merged to `main` before the DB migration was applied to
production, briefly leaving the live Settings panel showing schema-cache errors and
cosmetic "Disabled" tags (the app reading a not-yet-present `active` column). No user
was actually locked out (the middleware query failed closed to "not disabled") and
normal work was unaffected. Resolved by applying 0005 to production. **Lesson:** for
a package with both a schema change and app code, apply the schema to prod *before*
merging the app PR. Recorded for 1.6's release checklist.
