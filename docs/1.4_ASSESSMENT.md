# Package 1.4 — Protect campaign and financial integrity

Read-only assessment 11 Aug 2026, and the agreed build. Database-level guardrails;
**no app rewrite** — the app already writes valid data, these stop future
corruption from bugs, imports, or direct edits.

## Already tamper-proof (no action needed)
- `supplier_net` = gross − commission is a **generated column** — computed by the
  database, can't drift or be mis-edited.
- `client_invoices.vat` is generated (always 20%).
- Statuses, channels, OOH formats, copy instructions locked by check constraints.

## Gaps found → fixed in 1.4
| Gap | Fix |
|---|---|
| Money fields can go negative (gross, charge, fee, invoice amounts, lead value) | Non-negative CHECK constraints |
| `commission_pct` unbounded | CHECK 0–100 |
| A line could end before it starts | CHECK end_date ≥ start_date |
| Deleting a campaign silently shreds its issued invoices (cascade) | BEFORE DELETE trigger blocks it unless invoices are Draft/Cancelled |

## Decisions (11 Aug 2026)
- **Block deleting** a campaign with an issued client invoice. ✅
- **Allow edits** after invoicing — the invoice is a snapshot; no campaign lock.
- **Below-cost / negative margin** stays a dashboard **flag, not a block** — it can
  be a deliberate commercial call.

## Build
- `supabase/migrations/0004_integrity.sql` — the constraints + the delete-guard trigger.
- `supabase/VALIDATE_INTEGRITY.sql` — pre-flight; must return all zeros before 0004
  is applied to a database with real data (a constraint can't be added if existing
  rows violate it).

## Not in scope (deliberate)
- Locking campaign figures after invoicing (decided against — too rigid).
- Blocking below-cost lines (kept as a flag).
- Guarding supplier-invoice loss on delete (client invoices are the external record;
  the delete-guard targets those).
